# 原作资料系统收集流程（阶段 0a）

## 触发条件
- 新同人项目启动
- 交叉同人需要分别收集多部作品设定
- 对原作细节不确定，需要系统性梳理

## 流程

### 1. 确定收集范围
与用户确认：
- 涉及哪些作品
- 主要场景/设定焦点（如"冬木市"、"翁法罗斯"）
- 需要哪些维度（世界观、角色、地理、历史事件、力量体系等）

### 2. 多源并行收集
使用 `delegate_task` 并行收集，每个子任务负责一个维度。

**优先级信源：**
| 优先级 | 来源类型 | 示例 |
|--------|----------|------|
| ★★★★★ | 官方设定集/原作 | TYPE-MOON Complete Material、原作游戏攻略、崩铁官方世界观PV |
| ★★★★★ | 原作游戏攻略/流程 | B站攻略帖（含选项、好感度、结局触发条件）—— 对剧情梗概尤其重要 |
| ★★★★☆ | 官方Wiki / 百科 | Fandom Wiki、百度百科（需交叉验证） |
| ★★★☆☆ | 社区整理 | Reddit、NGA、贴吧精华帖 |
| ★★☆☆☆ | 同人约定俗成 | 广泛接受但非官方的设定补充 |

**搜索工具：**
- 国内内容优先使用 `multi-web-search` skill（百度/必应中国/搜狗等），比浏览器搜索更可靠
- 国际内容使用 `multi-web-search` 的 Google/Brave 引擎
- 搜索命令：`python3 ~/.hermes/skills/multi-web-search/scripts/search_hermes.py -q "查询内容" -e baidu,bing_cn,sogou`
- **不要只依赖训练数据写剧情梗概** — 训练数据对长篇作品的细节经常有偏差，必须查资料验证

**注意事项：**
- Fandom Wiki 可能被 Cloudflare 拦截，准备 Baidu Baike 作为备用源
- 百度百科的"编辑时间"可用于判断信息时效性
- 同一事实至少两个独立来源交叉验证
- **剧情梗概类文档必须与原作攻略/流程逐节点比对** — 不能凭记忆写，即使"大概知道"也要验证每个事件的时间线和触发条件

### 3. 可信度检查
每条信息标注可信度等级：
- ★★★★★：直接来自官方设定集/原作
- ★★★★☆：核心设定来自官方，细节来自社区整理
- ★★★☆☆：来自社区分析，可能存在推断成分

**冲突处理：** 不同来源有出入时，以官方设定集为准，在文档中标注差异。

### 4. 标准化输出
每个维度一个 markdown 文件，存入 `原作资料/` 目录：
- 文件头标注来源和可信度
- 使用统一格式（标题层级、表格、列表）
- 中文创作项目用中文输出

**必须产出的文件：**
- `README.md` — 索引文件，列出所有资料文件及简述

### 5. 输出结构示例
```
原作资料/
├── README.md                      ← 索引
├── 圣杯战争系统.md                ← 世界观/规则
├── 冬木市地理与关键地点.md        ← 场景设定
├── 角色图鉴-Master篇.md           ← 角色资料
├── 角色图鉴-Servant篇.md          ← 角色资料
└── 魔术体系与Nasuverse世界观.md   ← 力量体系
```

## 交叉同人的特殊处理
当项目涉及两部以上作品时：
1. 每部作品的资料独立存放在各自的子目录或用文件名前缀区分
2. 收集完成后，额外产出一份**交叉点分析**文档，梳理两部作品的设定兼容性
3. 标注需要"融合"或"取舍"的设定冲突点

## Pitfalls
1. **不要在收集阶段做融合** — 先忠实地记录每部作品的原始设定，融合是后续阶段的工作
2. **注意时效性** — 持续更新的作品（如崩铁）设定可能随版本更新，标注收集截止版本
3. **区分"设定"和"解读"** — 角色动机、未明说的因果关系属于解读，应标注为推断
4. **AI 收集的资料必须经用户审阅后才能作为权威来源** — AI 对长篇作品的细节记忆经常出错（角色阵营归属、力量分类、人物关系等），尤其是持续更新的多版本作品。收集完成后必须打包交给用户审阅，获取订正意见后才能用于后续创作。典型错误模式：
   - 角色阵营搞混（如将花火归入星核猎手而非假面愚者）
   - 角色身份张冠李戴（如将镜流写作"前云骑将军"而非"前任剑首"）
   - 力量体系分类错误（如宝具的"对军/对城/对界"分类）
   - 不同续作的设定混在一起（如崩坏3和崩铁是不同游戏，世界观有差异）
   - 对模糊记忆的事实做过度自信的断言（如"无限令咒"应标注为待核实）
5. **同系列不同作品的设定不要混用** — 崩坏3 ≠ 崩坏：星穹铁道，Fate/stay night ≠ Fate/Grand Order。同一IP下的不同作品可能有相同角色但不同设定，必须分开收集、明确标注来源作品。
6. **飞书环境下的文件交付** — 飞书机器人发送文件受限（MEDIA: 前缀在 send_message 中不生效，安全目录限制）。替代方案：(a) 将内容直接贴在消息中（适合短文本）；(b) 提示用户 SSH 直接查看服务器文件；(c) 将文件复制到 `~/.hermes/document_cache/` 后用 MEDIA: 在 agent 响应中附带（对 .md 文件效果待验证）。

### 6. 用户审阅与订正循环
收集完成后：
1. 将资料文件告知用户（列清单 + 文件路径）
2. 用户通过 SSH / 飞书 / 其他方式审阅
3. 用户给出订正意见
4. 逐条修改文档
5. 修改完成后可再次提交用户确认

**不要跳过用户审阅直接进入下一阶段。**
